## Oracle 與資料品質

- `referenceShanten()` 為原 PR #2 的**獨立完整目標建構 DP**：在同一物理四張牌上，尋找合法五面子一將眼的最大共同子牌數，而非重複正式 DFS 的面子／搭子貪婪搜尋。
- 快速測試會核對數個人工四槓、交錯組合、所有捨牌與已見牌減項。不可將抽樣符合宣稱為所有組合的數學證明。
- 大型驗證的每個 index 使用 `(masterSeed + imul(index, 0x9e3779b9)) >>> 0` 計算獨立 seed，測例可直接由 `regressionCase(masterSeed,index)` 重現。
- 大型驗證：**60%** 真實 136 張不放回均勻抽樣、**20%** 五面子一將眼構造後移除／擾動、**20%** 四槓極端牌，外加 4 個固定四槓樣本。16/17 張均檢查。任何失配皆列入總數並令 exit code 非零，前 12 筆顯示完整 `masterSeed/caseSeed/index/hand/expected/actual`。
- 現有 API 不包含完整 PlayerView：不能用本套件宣稱已排除整局暗牌洩漏、實戰勝率偏差、特殊和牌或公開副露支援。

## Benchmark 與統計解讀

`scripts/benchmark-suite.js` 輸出 schema 2，含 Node 版本、作業系統／版本、架構、CPU 型號、邏輯核心數、RAM、GitHub Runner 名稱（如有）、運行參數與預熱量。量測 `shanten` 及 `rankDiscards` 的 p50、p95、max、total（毫秒）與 checksum。比較 baseline 時需**同 schema、seed、case count、Node、OS 與 CPU 身分**；不同硬體直接拒絕，且同機器的 p95 偏差仍須排除系統負載與 JIT 雜訊。
